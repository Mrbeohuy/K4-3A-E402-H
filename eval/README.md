# CP3 Evaluation

This folder contains the CP3 golden set and evaluation runner.

## Current Data Status

- `golden_set.json` contains 28 cases.
- 10 cases are derived from real Discord chatlog patterns in `data/discord-pack/k4_messages.csv`.
- 18 cases are synthetic coverage cases for normal, source-truth, ambiguous, out-of-scope, domain, and rare behavior.
- Discord-derived cases store only `msg_id` plus a short excerpt. The raw data pack is not copied into `eval/`.
- Knowledge retrieval uses local `data/vlearn-pack/` transcript and slide snippets at runtime.
- `data/` must stay ignored and local-only.

## Existing Run 1 Caveat

`run1-results.json` and `run1-summary.md` are real Gemini artifacts from a pre-CP4 25-case golden set run. That run produced 25 total / 1 passed / 24 failed / 4.00%, mostly because Gemini returned quota/rate-limit errors.

After CP4, the current golden set has 28 cases. A fresh full eval against the 28-case set should be run when Gemini quota is available.

## Run 1

Run 1 must be generated by calling the real retrieval + Gemini pipeline:

```powershell
Copy-Item .env.example .env
# Fill GEMINI_API_KEY in .env before running eval.
python eval/run_eval.py
```

The eval runner sends only the top retrieved snippets for each case to Gemini. It does not upload the full VLearn or Discord pack.

If `GEMINI_API_KEY` is missing, the runner stops and does not create fake results.
